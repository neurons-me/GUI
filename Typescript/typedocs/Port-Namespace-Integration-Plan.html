Port is the transport — integration plan ​

Status 2026-10-15. Nothing here is integrated, published or deployed. Everything below was measured in isolated worktrees and disposable processes.

Contract ​

A port belongs to the transport, never to the namespace. name.space and name.space:8080 name the same namespace and are two transports; nothing (verification, session, credentials) passes between them; an explicit door is the only door; the same person coming back in is the same identity, and the identity a sign-in attempts is said before anything is signed.

Names, addresses and identity are three different things ​

  • A canonical name (name.space, what the monad canonicalizes a loopback to) is a spelling the system agrees on.
  • A network address (a host, a port, an origin) is where a request goes.
  • A verifiable identity is evidence that the actor behind a name is the same one as before (a signature, a claim, an authority record).

Canonicalizing a name proves none of the other two. suis-macbook-air.local is not globally unique (another network can have the same .local name); localhost and 127.0.0.1 mean "this machine" wherever they are read; cleaker.me is a DNS name whose control can change. "The same namespace" in this plan means "the same name", not "the same actor or tree": that continuity needs the evidence the claim flow already asks for (signed proofs against a claim), and nothing in this change weakens or replaces it.

A signed proof goes only to a destination that was selected ​

signIn/claim present a signature. Discovery may list candidates; a signature is presented only to: the origins the node was built for (preferred/space/bootstrap), the explicit fallbackOrigins (empty by default), what the page location or the operator's environment names, and the origin the signed namespace itself names. The machine hostname and the built-in defaults (public cleaker.me, localhost) are guesses: they no longer receive a proof when the primary fails (cleaker K13–K16). An explicit door (name.space:9901) is the ONLY door.

Behaviors worth a decision before integrating ​

  1. Fallback policy for addresses that named NO door. Measured (K14): with name.space unreachable, signed open proofs are sent to https://cleaker.me/claims/signIn and http://localhost/claims/signIn. This predates the change. An explicit door no longer does this; a bare address still does. Proposal: an explicit fallbackOrigins option, default empty for non-public roots.
  2. localhost is one namespace across ports (NS1 compat change). Several local monads that were distinguished only by port now need distinct names.
  3. Legacy monad session backend (createSeedSession.buildProof): not characterized, not claimed compatible.
