Port-is-the-transport — integration by reviewable parts (2026-10-15) ​

Nothing here is merged, published or deployed. The reference candidate (~/.get/candidates/port-is-transport-*) stays as the verified whole; this document splits it so each part can be reviewed and landed on its own.

Separation criterion: functional dependency (a later commit uses something an earlier one introduced; removing the earlier one breaks types or tests) is not the same as textual coupling (two commits edit the same lines of Namespace.tsx / QRConnect.tsx; reverting one conflicts). Only the first forces an order.

Evidence and its limits ​

  • Revert matrix (separability.revert-matrix.tsv in the from-scratch candidate): revert ONE commit from the topic head, then tsc and the unit suites. 3 interface commits revert cleanly; 1 is functional (types); the rest conflict textually. A revert conflict says later commits touch the same lines, not that they depend on it.
  • Identifier analysis: for each interface/position commit, the identifiers it introduces that a later link/port commit uses. It is a heuristic (a few hits are ordinary words); the real hits are hideBarItems, topBarLeftElements, RootCheck, sharedRootBinding, confirmedLabel, lastAttemptFailed, composePosition, positionComposed.
  • NOT done: building Part B and Part C as standalone stacked branches over cb79c8e0 WITHOUT Part D. The conflicts it needs are hand resolutions in Namespace.tsx and QRConnect.tsx; that is the next piece of work and would be reviewed hunk by hunk.

Order ​

A (anytime, independent) → the restructure that makes <Me>/<Cleaker>/QRConnect exist on main (a separate decision) → B → C → D in any order and independently. Acceptance per part: A npm test of cleaker (contract 22/22); B + C npm run test:runtime (vault 11, parser 7, mechanism 4, contract 4, integration 32) and npm run test:recorrido; the real-monad path with REAL_MONAD_SRC set (9/9).
